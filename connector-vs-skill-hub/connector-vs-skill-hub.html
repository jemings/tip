SLSI Agent Desktop · MyAvatar · 커넥터 · 2026-11

Agent Factory 카탈로그를 뒤지기 전에, 차려진 밥상부터

SLSI Agent Desktop이 이미 붙여 둔 커넥터를 MyAvatar가 쓰는 것은, 다 조리된 뜨끈한 요리를 바로 먹는 일이다. Agent Factory 카탈로그에서 각자 스킬을 찾아 쓰는 것은 냉동팩을 사 와서 집에서 조리하는 일이다.

쉽게 말하면냉동팩이 나쁜 것이 아니다. 이미 식탁에 올라온 요리가 있는데 굳이 냉동실부터 여는 이유를 묻는 자료다.

커넥터 = 요리회사가 만들어 두고, 자격·안전장치까지 붙어 나온다
카탈로그 스킬 = 냉동팩각자 고르고, 설치하고, 열쇠를 챙기고, 조리한다
기준SLSI Agent Desktop 3.260.0 · 사용 가이드
요약 — 먼저 결론

오늘 가져갈 세 문장

1. 같은 저울에 올릴 물건이 아니다

스킬은 할 줄 아는 일(레시피), 커넥터는 닿을 수 있는 곳(주방과 식재료 공급)이다. 레시피를 아무리 모아도 Jira에 닿는 길은 생기지 않는다.

2. 열쇠와 안전장치가 같이 나온다

사내 연동은 PAT 같은 열쇠를 서버가 쥐고, 쓰기·외부 전송 도구에는 앱이 "중요 작업" 표시를 붙여 묻는다. 각자 만든 길에는 이 표시가 없다.

3. MyAvatar는 혼자 쓰는 도구가 아니라 공유되는 설계도다

아바타 카드는 서버에서 팀에게 퍼진다. 모두가 같은 커넥터를 부품으로 쓰면 같은 카드가 누구 PC에서나 같게 돈다.

그래서순서는 커넥터 → 내 스킬 → Agent Factory 카탈로그다. 앱이 아바타 온보딩에서 정해 둔 순서와 같다. 카탈로그는 "없는 요리"를 보탤 때 연다.

03 — 먼저 갈라 놓을 것

스킬은 레시피, 커넥터는 주방과 식재료 공급이다

스킬 할 줄 아는 일

"이 일은 이렇게 한다"를 적은 문서와 스크립트. 에이전트가 읽고 따른다. 실행 환경(Windows/WSL)과 에이전트마다 따로 설치한다.

커넥터 닿을 수 있는 곳

에이전트에 도구를 붙여 주는 MCP 서버. 사내 시스템·내 지식·외부 서비스에 닿는 길 자체다. 사내 연동은 서버가 제공하는 만큼 카드가 자동으로 생긴다.

스킬 (Agent Factory 카탈로그)커넥터 (SLSI Agent Desktop)
비유냉동팩 + 레시피다 된 요리
주는 것일하는 방법시스템에 닿는 도구
시작하려면찾고 · 설치하고 · 필요한 준비를 한다카드가 이미 있다 (기본 켜짐)
설치 단위실행 환경 × 에이전트마다한 번 켜면 모든 에이전트에

쉽게 말하면"Agent Factory 카탈로그에서 골라 쓰면 되지 않나"는 질문은, 레시피 사이트를 뒤지면 식재료 공급이 해결된다는 말과 비슷하다. 둘은 서로를 대신하지 못하고 함께 쓴다.

스킬 쪽 "실행 환경 × 에이전트마다 설치"와 커넥터 쪽 "한 번 켜면 모든 에이전트"는 사용 가이드(스킬·커넥터 페이지)에 적힌 동작이다. 표의 "비유"는 발표자 정리다.

04 — 같은 부탁, 두 갈래 길

데워 먹느냐, 해동부터 하느냐

"이 Jira 이슈 담당자와 최근 코멘트를 알려 줘"

커넥터로 — 이미 차려진 카드

jira 커넥터
  1. 앱을 켜고 사내 SSO로 로그인한다 (쓰던 계정 그대로)
  2. 커넥터 화면에 jira 카드가 이미 켜져 있다
  3. 부탁한다 — 에이전트가 도구를 골라 부른다
이 PC에서는 로그인한 SSO 신원만 보낸다. 실행은 사내 서버가 한다.

카탈로그 스킬로 — 각자 조리

스킬 직접 설치 추정
  1. Agent Factory 카탈로그에서 Jira 스킬을 찾는다 (이름·설명·별점으로 가늠)
  2. 지금 쓰는 실행 환경·에이전트에 설치한다 (다른 쪽에서 쓰려면 다시)
  3. Jira 주소와 개인 액세스 토큰을 발급해 스킬이 읽는 자리에 둔다
  4. 사내 프록시·인증서 때문에 스크립트가 막히면 직접 푼다
  5. 그제서야 부탁한다
스킬이 스크립트로 Jira를 직접 부르는 방식이라면 이런 준비가 사람마다 반복된다.

쉽게 말하면식당에서는 앉아서 주문하면 끝난다. 냉동팩은 사 오고, 해동하고, 불을 켜고, 설거지까지 내 몫이다.

왼쪽 레인은 사용 가이드(커넥터 8절)와 README의 동작이다. 오른쪽 레인은 추정 — 카탈로그의 스킬마다 구성이 달라 모든 스킬이 이 단계를 다 거치지는 않는다. 다만 스킬 설치가 "실행 환경 × 에이전트마다"라는 점은 가이드에 그대로 적혀 있다.

05 — 열쇠는 누가 쥐나

PAT를 각자의 PC에 흩어 두지 않는다

사내 연동 서버가 쥔다

실제 실행과 자격 증명(PAT 등)은 사내 서버가 맡는다. PAT를 넣는 칸도 앱 안에 있고, 값은 서버의 내 환경변수 금고에 저장되어 이 PC에는 남지 않는다. 저장한 값은 다시 보여 주지 않는다. Knox처럼 서버가 자격을 관리하는 카드에는 입력 버튼조차 없다.

OAuth 커넥터 앱이 들고 있는다

Meetzy 같은 OAuth 로그인 커넥터는 앱이 로그인해서 받은 출입증을 암호화해 보관한다. 에이전트는 출입증 대신 앱 안의 중계 주소만 받고, 앱이 요청마다 최신 출입증을 붙인다. 화면·로그·에이전트 설정에는 싣지 않는다.

각자 만든 길 추정

스킬이 스크립트로 직접 부르는 방식이면 토큰은 스킬이 읽는 어딘가(환경변수·설정 파일)에 있어야 한다. 사람 수만큼 토큰이 PC에 퍼지고, 그 토큰이 어디에 있는지는 각자가 관리한다.

쉽게 말하면식당 주방의 열쇠는 식당이 갖고 있다. 냉동팩을 가져다 집에서 조리하면, 가스 밸브·냉장고 열쇠를 내가 들고 다녀야 한다.

"각자 만든 길" 칸은 추정이다. 카탈로그 스킬이 모두 그렇다는 뜻이 아니라, 서버를 거치지 않고 직접 부르는 스킬이라면 구조상 그렇다는 것이다.

06 — 안전장치

"이 도구는 쓰기다"를 서버가 알려 주고, 앱이 묻는다

중요 작업 배지 쓰기·외부 전송

사내 서버가 "이 도구는 입력을 회사 밖으로 보낸다" 또는 "이 도구는 쓰기다"(Knox 메일 보내기, Jira·Confluence 등록·수정)라고 표시한 도구가 있으면 카드에 중요 작업 배지가 붙는다. 이름이 아니라 서버의 표시로 정한다.

확인 후 실행 쓰기만 묻는다

승인 방식이 기본(확인 후 실행)이면 표시가 붙은 도구 호출만 승인 카드로 묻는다. 사내 연동은 쓰기 명령만 묻는다 — 조회는 막힘 없이 흐른다.

외부 전송은 처음에 꺼져 있다

웹 검색처럼 입력이 회사 밖으로 나가는 커넥터는 꺼진 채로 시작하고, 켤 때 경고가 뜬다. 에이전트는 대신 켜지 못한다 — 동의는 사람만 한다.

회사가 막은 연동은 우회되지 않는다

배포 설정으로 막은 연동은 화면·메뉴 어디에도 보이지 않고 에이전트도 쓸 수 없다. 이름을 바꾸거나 다른 이름으로 같은 연동을 등록해도 거절된다.

쉽게 말하면식당은 위생 점검을 받고 알레르기 표시를 붙여 낸다. 냉동팩은 포장지의 설명이 전부다.

스킬이 셸 스크립트로 서비스를 직접 부르는 경우, 앱이 "이 호출이 쓰기다"를 구분할 근거는 서버의 표시뿐인데 그 길에는 그 표시가 없다. 추정 — 위 배지·승인 규칙이 사내 연동 커넥터에 대해 가이드에 적혀 있고, 스킬 호출에는 같은 표시가 적혀 있지 않다는 데서 낸 해석이다.
07 — MyAvatar라서 더 중요한 이유

아바타 카드는 혼자 쓰는 메모가 아니라, 팀에 퍼지는 설계도다

카드는 서버에 있고, 공개 범위가 있다

아바타 카드는 Agent Factory 서버에 있고 온보딩이 각자의 PC에 설치한다. 공개 범위는 서버가 지원하면 전체 공개·팀 공개 중에 고르고, 지원하지 않으면 전체 공개로 등록된다. 즉 내가 만든 카드를 동료가 받아 쓴다.

역할마다 필요한 MCP 연결이 있다

내 아바타 화면은 역할 아이콘 색으로 상태를 알려 준다. 주황은 필요한 MCP 연결이 끊긴 것 — "도구 없이 실행될 수 있습니다"라는 경고가 붙는다.

온보딩은 이미 커넥터부터 찾는다

에이전트는 이 PC에 있는 것을 연결 가능한 커넥터 → 내 스킬 → Agent Factory 순으로 먼저 찾아 쓴다. 애매하면 번호로 고르게 한다.

모두가 같은 커넥터를 부품으로 쓸 때

카드가 "jira 커넥터로 읽는다"고 적으면 누구의 PC에서나 같은 부품이 있다. 받는 즉시 같은 방식으로 돈다.

사람마다 다른 카탈로그 스킬을 쓸 때 추정

카드가 카탈로그 스킬 이름을 가리키면 받는 쪽은 "그 스킬이 설치돼 있나, 같은 판인가"부터 확인해야 한다. 같은 카드가 PC마다 다르게 돌 여지가 생긴다.

쉽게 말하면한 팀이 같은 레시피북을 쓰려면 같은 주방 기구가 있어야 한다. 팀원마다 다른 기구를 쓰면 같은 레시피도 다르게 나온다.

08 — 한 번 켜면 어디서나, 고치면 모두 한꺼번에

관리해야 할 사본이 사람 수만큼 늘지 않는다

모든 에이전트에 한 번에

커넥터 탭에 등록한 MCP는 에이전트별 투영이 기본 켜짐이다. 한 번 갖춰 두면 Claude Code와 OpenCode 어느 쪽 대화에서나 쓴다. 아바타도 양쪽에 같은 모양으로 설치된다.

스킬은 사본이다

스킬은 실행 환경과 에이전트마다 따로 설치되는 사본이다. 새 판이 나오면 스킬 카드에 업데이트 표시가 뜨고 각자 다시 설치한다. 그 구조는 Agent Factory 스킬 업데이트 자료에 정리해 두었다.

서버가 고치면 모두 같은 날 추정

사내 연동은 실행이 서버에서 일어난다. 서버가 고치면 사용자 PC에 새 사본을 깔 필요 없이 같은 동작이 모두에게 닿는다고 보는 것이 자연스럽다.

쉽게 말하면식당 레시피를 바꾸면 모든 손님의 접시가 바뀐다. 냉동팩은 이미 팔려 나간 것은 그대로 남는다.

"서버가 고치면 모두 같은 날"은 가이드의 "실제 실행은 사내 서버가 맡는다"에서 이끌어 낸 추정이다. 구체적인 배포 일정은 서버 운영 쪽 사정에 따른다.

09 — 지금 차려진 메뉴

이미 있는 요리를 먼저 보자

사내 시스템 자동 생성

Knox · Jira · Confluence 등. 서버가 제공하는 연동마다 카드가 자동으로 생기고 기본으로 켜져 있다. 슬라이드·다이어그램(drawio) 같은 연동은 결과물을 서버 보관함에 저장하고 채팅의 결과물 탭에 모아 준다.

내 지식 이 PC에서

Mail Knowledges · Document Knowledges. 지정한 메일·문서 폴더가 재료가 된다. 문서 지식은 접근 키와 허용 IP로 팀원의 PC가 검색하게 열 수 있고, 메일 지식은 다른 PC와 나누지 않는다.

회의록 등 OAuth 서비스

Meetzy처럼 로그인으로만 붙는 서비스는 카드의 [연결하기] 한 번으로 끝난다. 관리자가 모든 사용자 화면에 미리 깔아 둘 수도 있다.

웹 검색은 꺼짐이 기본

앱 도구 web_fetch는 이 PC의 망(사내 프록시·인증서)으로 웹 페이지를 읽어 준다. 웹 검색 커넥터는 외부 전송이라 처음에 꺼져 있고 켜려면 경고에 동의해야 한다.

API 없는 화면 꺼짐이 기본

SLSI Browser는 앱 전용 Edge 창에서 근태·결재처럼 API가 없는 사내 화면을 사람처럼 누르고 입력한다. 비밀번호는 읽지도 넣지도 못한다.

DRM 사내 문서 기본 탑재 스킬

이 카드만 커넥터가 아니라 앱에 기본으로 들어 있는 스킬이다. ds-docvision이 Word · PowerPoint · Excel · PDF를 설치된 Office로 다룬다. 고치기 전에 백업하고 실패하면 되돌린다. 스킬도 앱이 먼저 챙겨 주는 것이 있다는 예다.

연동 목록은 사내 서버의 설정과 배포 정책에 따라 사용자마다 다를 수 있다. 위는 사용 가이드와 README에 적힌 대표 예다. 어느 카드가 보이는지는 앱의 커넥터 화면에서 확인한다.

10 — 예상되는 반론

"Agent Factory 카탈로그 뒤져서 각자 쓰면 되지 않나요?"

반론답
"내게 맞는 걸 고르는 게 더 낫다"고르는 비용이 사람 수만큼 든다. 같은 Jira에 닿는 스킬을 열 명이 열 번 찾고, 판이 다르고, 결과가 다르다. 고르는 일을 한 번 해 둔 것이 커넥터다.
"스킬 하나면 Jira도 되는데?"되는 스킬이 있을 수 있다. 그 스킬이 어떤 열쇠로, 어떤 길로 부르는지는 설치한 사람이 확인해야 한다. 커넥터는 서버가 열쇠를 쥐고, 쓰기에는 앱이 묻는다.
"커넥터에 없는 일은요?"그때가 스킬 차례다. 앱 온보딩도 "새 기능이 필요할 때만" 커넥터 다음에 카탈로그를 찾는다. 반대가 아니다.
"커넥터는 내가 못 고친다"맞다. 대신 직접 등록도 된다 — 원격(HTTP)·로컬 실행·JSON 방식. 쓰고 싶은 MCP가 있으면 커넥터 화면의 [커넥터 등록]으로 붙인다.
"카탈로그가 더 최신 아닌가요?"스킬의 최신판을 쓰는 것이 필요한 일이라면 스킬을 쓰면 된다. 다만 시스템에 닿는 길을 최신으로 유지하는 일을 사용자마다 하게 하지는 않는다는 것이 이 자료의 요지다.

쉽게 말하면"요리 솜씨가 있으니 냉동팩이 낫다"는 말은 맞을 수 있다. 하지만 팀 전원이 매일 같은 점심을 먹어야 한다면 식당이 낫다.

11 — 공정하게 보면

그래도 냉동팩이 맞는 때

커넥터가 맞는 때

  • 사내 시스템(Knox·Jira·Confluence)에 닿아야 할 때
  • 내 메일·문서를 찾아 쓸 때
  • 아바타 카드를 팀에 공유할 때
  • 쓰기·외부 전송에 승인과 차단이 필요할 때
  • PAT·출입증을 PC에 흩어 두고 싶지 않을 때

스킬(Agent Factory 카탈로그)이 맞는 때

  • 일하는 방법을 붙이고 싶을 때 — 보고서 문체, 검토 절차, 코딩 규칙
  • 커넥터에 아직 없는 개인 업무의 반복 작업
  • 외부 서비스 없이 이 PC 안에서 끝나는 작업
  • Agent Factory 카탈로그에 이미 검증된 팀 표준 스킬이 있을 때
  • 커넥터가 줄 수 없는 전문 도메인 지식을 입힐 때

쉽게 말하면밥은 식당에서, 입맛에 맞는 양념은 내 냉장고에서. 둘은 경쟁하지 않는다. 다만 순서가 있다.

MyAvatar도 스킬을 쓴다. 이 자료는 "스킬 금지"가 아니라 "시스템에 닿는 길은 커넥터로 통일하자"는 제안이다.

12 — 권하는 순서

MyAvatar를 만들 때: 커넥터 → 내 스킬 → Agent Factory 카탈로그

1. 커넥터 화면부터 본다

내가 쓸 시스템이 이미 카드로 있는지 확인한다. 있으면 켜져 있는지, 중요 작업 배지가 있는지, PAT 입력이 필요한지 본다.

2. 내 스킬로 방법을 붙인다

"어떻게 하는지"는 내 업무 방식이다. 스킬 한 장(SKILL.md)으로 붙인다. 이미 써 둔 내 스킬이 있으면 그것부터 쓴다.

3. 모자라면 카탈로그를 연다

커넥터에도 내 스킬에도 없는 일만 Agent Factory에서 찾는다. 설치 전에 누가 만들었고 무엇을 하는지 본다.

한 줄 점검표 — ① 닿아야 할 곳이 커넥터에 있는가 ② 쓰기·외부 전송이 있다면 승인 방식을 정했는가 ③ 카드에 쓴 부품 이름을 팀원도 가졌는가 ④ 카탈로그 스킬을 더했다면 판과 출처를 적어 뒀는가

쉽게 말하면먼저 식당 메뉴판을 보고, 없는 것만 마트에서 사 온다.

정리

냉동팩은 훌륭한 식재료다. 하지만 점심은 식당에서 먹자.

커넥터를 쓰면

준비 없이 닿고, 열쇠는 서버가 쥐고, 쓰기는 앱이 묻고, 팀의 아바타 카드는 같은 부품으로 돈다.

카탈로그 스킬은

커넥터에 없는 방법과 도메인을 보탤 때 쓴다. 순서는 커넥터 → 내 스킬 → Agent Factory 카탈로그.

한 문장MyAvatar는 SLSI Agent Desktop이 차려 둔 커넥터를 먼저 쓰자 — 뜨끈한 요리가 이미 식탁에 있다.
