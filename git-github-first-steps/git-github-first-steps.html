헷갈리는 두 이름

Git과 GitHub는 다른 거야

내 컴퓨터에 까는 프로그램

Git

지금까지 본 세이브 포인트·연습장 기능 그 자체야. 인터넷이 없어도 내 컴퓨터 안에서 혼자 돌아가.

≠
인터넷에 있는 웹사이트

GitHub

Git으로 기록한 프로젝트를 기록째로 올려 두는 온라인 집이야. 백업되고, 다른 사람과 같이 쓰고, 공개해서 보여 줄 수도 있어.

Git : GitHub = 카메라 : 인스타그램 카메라만 있어도 사진은 찍을 수 있지(Git). 인스타에 올리면 안전하게 보관되고, 친구에게 보여 주고, 댓글도 받을 수 있어(GitHub).

노트북이 고장 나도 GitHub엔 다 남아 있어. 학교 컴퓨터에서 받아 와서 이어 하면 끝!

각자 자기 브랜치에서 일하고, 끝나면 본문(main)에 합쳐. 누가 언제 뭘 바꿨는지 전부 남아.

풀 리퀘스트(Pull Request, PR)

“내가 고친 거, 한번 봐 줄래?”

옆길에서 작업을 끝내면 바로 본문에 넣지 않고 팀원에게 검토를 부탁해. 그 부탁이 Pull Request야.

팀원은 바뀐 줄을 보면서 댓글을 달고, 고칠 게 없으면 승인해. 승인이 나면 버튼 하나로 본문에 합쳐져.

왜 이름이 ‘Pull’ Request냐면?
“내 변경을 당겨(pull) 가 줘”라는 부탁이라서. 이름만 어렵지 뜻은 검토 요청이야.

3장 실험 결과 정리 #7

    지수가 검토를 요청했어

    “3장 실험 결과 정리했어! 한번 봐 줄래?”

  2. ±
    바뀐 내용: +12줄 −3줄 · 표 1개, 그래프 1개

  5. 하

    “좋아, 이대로 합치자!”

  6. ⑂
    본문(main)에 합쳐졌어 🎉

GitHub 화면이 읽히는 단어장

이 열두 단어만 알면 돼

📦Repository
저장소

프로젝트 하나를 담는 폴더. 그 폴더의 모든 역사까지 함께 들어 있어. 줄여서 repo.

💾Commit
세이브 포인트

지금 상태를 메모와 함께 기록하기.

🌱Branch
연습장 · 옆길

본문을 건드리지 않고 따로 실험하는 길.

🔀Merge
합치기

옆길에서 한 작업을 본문에 합치기.

📘main
본문

모두가 “이게 진짜”라고 약속한 기본 브랜치.

🔄Push / Pull
올리기 / 받아오기

내 컴퓨터와 GitHub 사이를 맞추기.

📥Clone
통째로 받아오기

GitHub의 저장소를 기록째 내 컴퓨터로 복사.

⑂Fork
내 계정으로 복사

남의 저장소를 내 GitHub로 가져와 마음대로 고치기.

🙋Pull Request
검토 요청

내 변경을 합쳐 달라고 부탁하고 의견 받기. 줄여서 PR.

📌Issue
할 일 · 질문 쪽지

고칠 것, 아이디어, 질문을 적어 두는 게시판.

📖README
표지 · 설명서

저장소에 들어오면 제일 먼저 보이는 소개 글.

⭐Star
즐겨찾기

마음에 드는 저장소에 별을 달아 두기. ‘좋아요’ 같은 것.

다 기록돼 있으니까.

Git은 실수를 막는 도구가 아니라, 실수해도 돌아올 수 있게 해 주는 도구야. GitHub는 그 기록을 안전하게 보관하고, 친구들과 나누고, 세상에 보여 주는 곳이고.

궁금한 게 생기면 언제든 물어봐. 첫 커밋, 같이 해 보자!

이 안내서도 Git으로 만들었어. 고칠 때마다 찍은 세이브 포인트는 여기서 볼 수 있어.
