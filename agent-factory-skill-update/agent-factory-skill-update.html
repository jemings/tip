스킬이 새 버전이 됐다. 내 PC의 스킬은 언제 바뀔까?

npx skills add로 받은 스킬은 내 PC에 복사본으로 남는다. 서버에서 새 버전이 나와도 복사본은 그대로다. 이 발표는 그 틈을 어떻게 메웠는지 서버부터 Claude Code 세션 시작 hook까지 한 바퀴 따라간다.

쉽게 말하면서버는 “지금 나눠 주는 버전의 지문”만 공개한다. 내 PC는 Claude Code 세션을 열 때 자기 복사본의 지문을 떠서 맞대 본다. 다르면 Claude가 “업데이트가 있어요”라고 알려 준다.

0명업데이트 확인 때 서버가 기록하는 사용자
2초세션 시작 때 확인 예산
24시간기본 확인 주기(TTL)

02 — 먼저 결론

세 문장으로 요약하면

1. 판정은 내 PC가 한다

CLI로 설치하면 서버는 누가 무엇을 설치했는지 모른다. 그 익명성을 지키려고 서버는 공개 인덱스만 내고, 비교는 사용자 PC가 한다.

2. 버전 번호가 아니라 지문으로 비교한다

설치된 폴더의 파일 트리를 해시한 값(tree_sha256)을 서버 값과 맞댄다. 설치 도구가 무엇이든 같은 방법으로 비교할 수 있다.

3. 스킬을 쓰는 자리에서 알린다

Claude Code 세션이 시작될 때 hook이 확인하고 Claude에게 안내를 넣는다. 갱신은 기존 npx skills add 명령이 한다. 자동 재설치는 켠 사람에게만, 백업과 검증을 거쳐 한다.

한 줄로“서버가 알림을 쏘는” 구조가 아니라 “PC가 세션 시작 때 물어보는” 구조다.

03 — 문제

서버는 누가 설치했는지 모른다

CLI로 설치하는 경로는 대부분 익명 URL이다. 누구에게나 똑같은 주소라서 팀 채팅에 붙여 넣어도 된다. 대신 서버는 설치한 사람을 알 수 없다.

설치 경로명령 / 주소서버가 설치자를 아는가
npx skillsnpx skills add <origin>/skills/<short_id>모른다 — 익명 URL
카탈로그 마켓플레이스Claude Code /plugin marketplace add …모른다 — 고정 익명 URL
GitHub 직행원본 저장소에서 바로 설치모른다 — 서버를 거치지 않는다
웹 ZIP 다운로드로그인한 브라우저에서 내려받기안다 — 설치 이벤트를 남긴다
Agent APIAPI 키로 archive 받기안다 — 설치 이벤트를 남긴다

익명은 일부러 그렇게 만든 것이다

short_id는 추측할 수 없는 무작위 12자다. 주소를 아는 것 자체가 접근 권한이라(capability URL) 로그인 없이 받는다. 접근 로그는 short_id와 토큰을 가린다. 로그인하지 않은 요청은 접근 기록 테이블에 남기지 않는다. 바꿀 생각이 없는 원칙이다.

알리는 곳과 쓰는 곳도 다르다

웹 알림은 브라우저에서 본다. 스킬은 에이전트 세션에서 쓰인다. 웹 알림을 받아도 CLI 사용자는 놓치기 쉽다.

그래서 “서버가 설치자 명단을 들고 알림을 보낸다”는 방식은 쓰지 않는다. 명단을 만들려면 익명 URL을 사람마다 다르게 바꿔야 하는데, 그러면 익명성 원칙이 깨진다. 그래서 이 방식은 검토 단계에서 기각했다(06의 A안).
04 — 용어

업데이트 = serving 버전이 앞으로 움직인 것

스킬은 여러 버전을 갖는다. 서버는 그중 하나를 serving 버전으로 정해 서버를 거치는 설치 경로(npx skills·카탈로그 마켓·웹·API)에 내준다. 버전이 바뀔 때마다 “보안 검사를 통과한(verified) 버전 우선, 그다음 최신 순번(seq)” 규칙으로 다시 골라 저장한다. 관리자가 특정 버전으로 되돌리면 그 버전에 핀이 걸려, 핀을 풀 때까지 자동 규칙이 덮어쓰지 않는다.

seq 5verified
seq 6verified
seq 7verified · serving
seq 8pending · 검사 중

앞으로 업데이트

seq 8이 검사를 통과하면 serving이 8로 바뀐다. 처음부터 verified로 발행돼도 같다.

제자리 아무 일 없음

seq 8이 아직 검사 중이거나 검사에서 걸리면 serving은 7에 머문다. 새 버전을 냈다고 업데이트가 아니다.

뒤로 후퇴

관리자가 이전 버전으로 되돌리거나, 재검사로 serving 버전이 강등되면 serving이 6으로 내려간다. 업데이트와 따로 알린다.

그래서“업데이트가 있다”는 판단의 기준은 발행 시각이 아니라 serving 버전이다. 사용자 PC가 비교해야 할 대상도 serving 버전이다.

08 — 서버

익명 인덱스에 필드 세 개를 더했다

// GET <origin>/skills/<short_id>/.well-known/agent-skills/index.json
{
  "name": "pdf-tools-af03",      // 설치 이름
  "type": "archive",
  "url": "pdf-tools-af03/archive",
  "digest": "sha256:…",          // zip 해시 (기존)
  "x-agent-factory": {
    "seq": 7,                     // serving 버전 순번
    "version_label": "1.4.0",    // 사람이 읽는 이름
    "tree_sha256": "f74d…"      // 풀었을 때의 지문
  }
}

seq — 앞인가 뒤인가

지난번에 본 seq보다 크면 업데이트, 작으면 후퇴다. 지문만으로는 “달라졌다”까지만 안다.

tree_sha256 — 같은가 다른가

zip을 풀었을 때 나오는 파일 트리의 해시. PC는 설치 폴더를 같은 방법으로 해시해 맞댄다(09). 스킬 항목마다 따로 붙어서, 한 아이템에 스킬이 여럿이면 seq는 같고 지문은 저마다 다르다.

호환성

x- 접두 필드라 이 인덱스를 읽는 다른 클라이언트는 모르는 키를 무시한다. 사용자 정보는 들어가지 않는다.

ETag와 304

응답 본문 전체의 해시로 weak ETag를 만든다. PC가 If-None-Match로 다시 물으면 바뀐 게 없을 때 본문 없이 304만 돌려준다. 하루 한 번 확인하는 비용이 거의 없다.

왜 본문 전체로 ETag를 만드나

zip이 그대로여도 seq·version_label·설명은 바뀔 수 있다. 필드를 골라 ETag를 만들면 빠뜨린 필드의 변경을 304가 가린다. 지문 계산 결과는 프로세스 캐시에 둬서 재확인 때 zip을 다시 만들지 않는다.

09 — 지문

왜 zip 해시가 아니라 파일 트리 해시인가

zip 해시(digest)로는 안 된다

PC에 있는 것은 zip이 아니라 풀어 놓은 폴더다. 폴더에서 원래 zip의 해시를 되살릴 방법이 없다. npx skills lock의 해시도 원본 저장소 기준이라 서버 값과 직접 비교할 수 없다.

그래서 “풀었을 때의 지문”을 정의했다

서버는 zip에 담을 파일로, PC는 설치 폴더로 같은 알고리즘을 돌린다. 설치 도구나 lock 형식과 상관없이 폴더만 있으면 비교할 수 있다.

  1. 트리 안의 일반 파일만 모은다. 경로는 루트 기준 상대 경로, 구분자는 /.디렉터리·권한·수정 시각은 넣지 않는다. 트리 안의 심볼릭 링크는 따라가지도 넣지도 않는다. 단, 설치 폴더 자체가 링크(npx skills의 기본 설치)면 실제 폴더로 풀어서 해시한다.
  2. 경로를 UTF-8 바이트 순서로 정렬한다.로캘이나 대소문자 무시 정렬이 아니다. Windows·macOS·Linux에서 같은 순서가 나온다.
  3. 파일마다 경로 바이트 + 0x00 + 내용 바이트를 정렬 순서대로 하나의 SHA-256에 넣는다.
  4. 소문자 16진 64자로 낸다. 빈 트리는 빈 입력의 SHA-256이다.
// 서버(Python)와 plugin(Node.js)이 함께 쓰는 시험 벡터
{"SKILL.md": "# hi\n", "b/z.txt": "z", "a.txt": "", "한.md": "k", "B.txt": "cap"}
→ f74d2f80e7ad6029d0250fae4d621a1792c54a93da19537d2973b56622321a8a

설치 폴더에 .DS_Store처럼 로컬에서 생긴 파일이 있으면 지문이 달라져 “로컬 수정”으로 판정된다. 자동 재설치를 하지 않는 쪽으로 틀리므로 안전하다.

10 — 설치본 찾기

hook은 어떤 스킬을 확인하나

  1. lock 파일을 읽는다전역 ~/.agents/.skill-lock.json, 프로젝트 skills-lock.json. 둘 다 npx skills가 쓴다.
  2. Agent Factory 것만 고른다source가 <origin>/skills/<short_id> 아래인 항목만. GitHub에서 직접 받은 스킬은 건드리지 않는다.
  3. 폴더가 실제로 있는지 본다~/.claude/skills/<설치 이름> 또는 프로젝트의 .claude/skills/<설치 이름>.
  4. (이름, short_id, 범위, 경로)로 묶는다같은 이름이 전역과 프로젝트에 모두 있으면 둘 다 따로 판정한다.

설치 이름 = 키 + -afNN

스킬을 올릴 때 쓴 SKILL.md의 name: 뒤에 서버가 구별용 접미사를 붙인다. 예: pdf-tools → pdf-tools-af03. 다른 사람이 같은 이름의 스킬을 올려도 폴더가 겹치지 않는다.

설치 폴더, lock 키, 재설치 명령의 -s, 백업 경로가 모두 이 이름을 쓴다. 그래서 hook은 이름을 인덱스의 name에서 읽는다.

origin은 어디서 정하나

환경변수 AGENT_FACTORY_ORIGIN → 사용자 설정의 origin → plugin에 동봉한 config.json 순서. 비어 있으면 hook은 아무것도 하지 않는다.

파일 하나짜리 컴포넌트(agent·command·theme)는 대상이 아니다. 루트에 SKILL.md가 없어 npx skills가 설치하지 않으므로 비교할 설치본이 없다.

11 — 판정

세 값을 맞대면 여섯 가지 답이 나온다

L — 지금 내 폴더

hook이 설치 폴더를 직접 해시한 값.

S — 지금 서버

인덱스의 tree_sha256. serving 버전의 지문.

R — 마지막으로 같았던 순간

L과 S가 같았을 때 hook이 적어 둔 (지문, seq). ~/.agent-factory/update-state.json에 있다.

조건판정자동 재설치
L = S최신. R ← (L, seq)로 갱신—
L ≠ S, L = R, seq > R.seq업데이트. 내 폴더는 손대지 않았고 서버가 앞으로 갔다허용
L ≠ S, L = R, seq < R.seq후퇴. 서버가 이전 버전으로 돌아갔다허용
L ≠ S, L = R, seq = R.seq같은 버전의 내용 변경. 원인을 알 수 없다금지
L ≠ S, L ≠ R로컬 수정 + 서버 변경. 재설치하면 고친 내용이 사라진다금지
L ≠ S, R 없음변경됨(구분 불가). 한 번도 최신으로 확인된 적 없는 설치본(예: plugin 설치 전부터 있던 것)금지

R이 열쇠다L과 S만 보면 “다르다”까지만 안다. R이 있어야 “내가 고친 건가, 서버가 바뀐 건가”를 가를 수 있다. 자동 재설치는 “서버와 같았던 뒤로 아무도 손대지 않은” 설치본에만 한다.

12 — 따라가 보기

pdf-tools 하나로 판정을 따라가 보자

  • 월요일
    npx skills add로 pdf-tools를 설치한다. 서버 serving은 seq 7, 지문 aaa.
  • 화요일
    세션 시작. L = aaa, S = aaa → 최신. R ← (aaa, 7).
  • 수요일
    작성자가 seq 8을 내고 검사를 통과한다. serving이 8, 지문 bbb로 바뀐다.
  • 목요일
    세션 시작(24시간 지남). 인덱스를 다시 묻는다.
L — 내 폴더aaa
S — 서버bbb · seq 8
R — 지난 기록aaa · seq 7
업데이트L = R이고 seq가 7 → 8로 올랐다. 내 폴더는 그대로고 서버가 앞으로 갔다. 자동 재설치를 켰다면 이 자리에서 다시 설치한다.

지문은 설명을 위해 aaa·bbb로 줄였다. 실제로는 64자 16진수다.

13 — 시간

hook 한 번의 시간표

확인 2초
재설치 구간 최대 120초 — 자동 재설치를 켠 경우만
여유
0s~122s150s

막대 폭은 실제 비율이 아니다. 150초는 Claude Code가 hook을 강제로 끊는 시간(hooks.json)이다.

확인 구간 전체 2초

  1. 설정 읽기 — check: false면 끝
  2. 마지막 확인이 24시간 이내면 네트워크 없이 캐시된 판정만 쓴다
  3. 설치본 수집
  4. short_id마다 인덱스 GET — 요청당 1.5초, ETag로 304
  5. 지문 계산 → 판정. 파일 5,000개나 64 MiB를 넘으면 계산 포기

2초를 넘기면 그 자리에서 멈추고 아무것도 출력하지 않는다.

재설치 구간 예산 밖

npx는 2초 안에 끝날 수 없어서 확인 구간 뒤에 따로 돈다. 한 건에 60초, 구간 전체 120초.

세션과 떨어진 백그라운드로 돌리지 않는다. 결과를 같은 세션의 안내에 실어야 하고, 이미 시작한 세션이 읽는 폴더를 뒤에서 바꾸면 안 되기 때문이다. 이 대기는 자동 재설치를 켠 사람만 치른다.

일시 실패 → 다음 세션에 다시

네트워크 오류·타임아웃·5xx가 하나라도 있으면 확인 시각을 남기지 않는다. 다음 세션이 다시 묻는다. 304 덕분에 싸다.

404·410 → 확정

스킬이 내려갔다는 확정 응답이다. 그 항목만 “확인 못 함”으로 두고 TTL(기본 24시간) 동안 다시 묻지 않는다.

14 — 안내

Claude가 세션 첫머리에 받는 글

hook은 표준 출력의 hookSpecificOutput.additionalContext에 안내를 싣는다. Claude Code는 이 글을 첫 프롬프트 전에 모델 컨텍스트에 넣는다. Claude가 읽고 사용자에게 전한다.

Agent Factory 스킬 설치본 확인 결과다. 아래 내용을 사용자에게 알리고, 재설치 명령은 사용자가 원할 때만 실행한다.
- pdf-tools-af03 (전역): 업데이트가 있다 (`1.3.0` → `1.4.0`). 재설치: npx skills add <origin>/skills/<short_id> -s pdf-tools-af03 -a claude-code -g --copy -y
- report-kit-af01 (프로젝트 — 그 디렉터리에서 실행): serving 버전이 바뀌었고 설치본에 로컬 수정이 있다 (`2.0.0` → `2.1.0`). 재설치하면 고친 내용이 사라진다. 재설치: npx skills add …

명령은 설치 때 모양 그대로

전역 설치면 -g, 링크가 아닌 실제 폴더면 --copy를 붙인다. 대상 에이전트는 -a claude-code로 고정이다. lock이 설치 때의 대상 에이전트를 남기지 않기 때문이다.

작성자 문자열은 걸러서 넣는다

version_label은 작성자가 정한 문자열이 모델 컨텍스트에 그대로 들어가는 자리다. 제어·서식 문자를 지우고, 백틱을 바꾸고, 64자로 자른 뒤 코드 표기로 감싼다.

길이에 상한이 있다

안내는 10,000자를 넘지 않는다. 넘으면 “… 외 N개 생략”으로 줄인다. 실행 여부는 사용자가 정한다는 문장이 맨 앞에 온다.

위 예시의 스킬 이름과 버전은 설명을 위해 지어낸 값이다. 문장 형식은 plugin의 notice.mjs를 그대로 옮겼다.

15 — 자동 재설치

켠 사람에게만, 일곱 단계를 거쳐

  1. 대상 조건 — R이 있고 L = R, seq가 움직임(업데이트·후퇴), 링크가 아닌 복사 설치본한 번도 최신으로 확인되지 않은 설치본, 로컬 수정이 있는 설치본은 안내만 한다.
  2. 잠금 — ~/.agent-factory/reinstall.lock을 O_EXCL로 만든다다른 세션이 쥐고 있으면 이번엔 안내만 하고 다음 세션에서 다시 시도한다. 10분 넘은 잠금은 버려진 것으로 본다.
  3. 백업 — 실제 폴더를 backup/<이름>/<경로 해시>/<시각>/에 복사백업에 실패하면 재설치하지 않는다. 설치본마다 최근 5개만 남긴다.
  4. 재확인 — 백업의 지문이 판정 때의 L과 같은가다르면 판정 뒤에 사용자가 고친 것이다. 백업을 지우고 “로컬 수정”으로 안내한다.
  5. 설치 — npx skills add … -y, 한 건에 60초
  6. 검증 — 설치 후 지문이 S와 같은가
  7. 복원 — 실패·시간 초과·지문 불일치면 백업을 되돌리고 안내로 강등“자동 재설치에 실패해 원래 설치본으로 되돌렸다”를 안내에 싣는다.

왜 링크 설치본은 빼나

npx skills의 기본 설치는 .agents/skills/ 원본을 여러 에이전트가 링크로 나눠 쓰는 형태다. -a claude-code 하나로 다시 설치하면 Claude Code 쪽만 새 사본이 되고 공유 원본은 옛 버전에 남는다. 그래서 안내만 하고, 다른 에이전트의 -a도 붙이라고 덧붙인다.

Windows 인자 검사

Windows의 npx는 npx.cmd라서 셸을 거친다. origin은 사용자가 정하는 값이므로 영숫자와 ._:/@+=~- 밖의 문자가 있으면 실행하지 않는다.

세션 시작 때만

세션 도중에는 재설치하지 않는다. 쓰고 있는 스킬이 대화 중간에 바뀌면 동작이 흔들린다.

16 — fail-safe

무슨 일이 있어도 세션 시작을 막지 않는다

오프라인·프록시

인덱스를 못 받으면 “확인 못 함”. 새 안내는 없다.

설정이 깨졌다

JSON이 틀리거나 타입이 맞지 않으면 아무것도 하지 않는다.

캐시가 깨졌다

update-state.json.corrupt로 옮기고 조용히 끝난다. 다음 세션은 빈 캐시로 시작한다.

예외·시간 초과

어느 단계든 아무것도 출력하지 않고 exit 0.

원칙 확인하지 못했으면 아무 말도 하지 않는다. 틀린 안내보다 안내가 없는 편이 낫다. 설치본은 그대로 동작한다.

왜 조용했는지 보려면

이유는 stderr에 agent-factory-update-check:로 시작하는 한 줄로 남는다. exit 0의 stderr는 모델 컨텍스트에 들어가지 않고 claude --debug 로그에서만 보인다.

프록시 환경 주의

인덱스 요청은 Node.js 내장 fetch를 쓴다. 내장 fetch는 기본으로 HTTPS_PROXY를 따르지 않는다. 프록시를 거쳐야만 닿는 origin이면 확인이 실패해 조용히 넘어간다.

17 — 사용자 쪽

사용자가 만지는 것은 파일 하나다

// ~/.agent-factory/update-check.json (없으면 기본값)
{
  "check": true,             // false면 hook이 아무것도 안 한다
  "ttl_hours": 24,           // 0이면 매 세션 확인
  "auto_reinstall": {
    "default": false,        // 기본은 안내만
    "skills": {
      "pdf-tools-af03": true // 이 스킬만 자동
    }
  },
  "origin": "https://…",     // 생략하면 plugin 동봉값
  "reinstall_timeout_seconds": 60
}

설치가 곧 동의다

카탈로그 마켓플레이스에서 agent-factory-update-check plugin을 설치하면 다음 세션부터 돈다. 설치하지 않으면 아무 일도 없다. 단, 동봉 config.json의 origin이 비어 있으면 hook은 아무것도 하지 않는다 — 배포 때 채우거나 사용자가 origin을 적어야 한다.

끄는 법

"check": false를 두거나 plugin을 제거한다. 캐시와 백업까지 지우려면 ~/.agent-factory/를 지운다.

hook이 쓰는 파일

update-state.json(확인 시각, 설치본별 R, ETag 캐시) · backup/ · reinstall.lock. plugin 캐시는 버전마다 폴더가 바뀌므로 홈의 고정 경로에 둔다.

실제 파일은 주석 없는 JSON으로 쓴다. 이 plugin 자신은 제3자 마켓 소속이라 자동 갱신이 기본 꺼짐이다. 필요하면 /plugin 메뉴에서 마켓 자동 갱신을 켠다.

18 — 웹

로그인 사용자에게는 웹 알림도 간다

웹 알림은 보조 채널이다. 웹에서 내려받았거나 설치 명령을 복사한 로그인 사용자에게 간다. 이번 작업에서 함께 바로잡았다.

알림 시점을 serving 기준으로

전에는 새 버전을 발행하는 순간 알림이 나갔다. 검사에서 걸려 serving이 되지 못한 버전도 알렸다. 이제는 serving이 바뀔 때만 보낸다.

후퇴도 알린다

serving이 앞으로 가면 skill_version_update, 뒤로 가면 skill_version_rollback. 전에는 후퇴 알림이 없었다.

스킬 단위로 알림 끄기

알림 메뉴에서 “이 스킬 알림 끄기”. 받은 알림 페이지의 “알림을 끈 스킬” 목록에서 다시 켠다.

카탈로그가 갱신을 막지 않게

Claude Code는 마켓 항목에 version이 있으면 그 문자열이 바뀔 때까지 갱신하지 않는다. 작성자가 라벨을 안 올리면 갱신이 멈췄다. 이제 version을 싣지 않고 archive sha256으로 판정하게 했다.

19 — 검증

어떻게 믿을 수 있나

단위·프로세스 테스트 node --test

  • 판정표 여섯 경우
  • 네트워크 실패·타임아웃·예산 초과·깨진 JSON → 출력 없이 exit 0
  • 일부 short_id만 일시 실패 → 다음 세션 재조회
  • 자동 재설치: 로컬 수정 거부, 판정 뒤 수정 재확인, 잠금, 실패·불일치·시간 초과 시 복원, 백업 정리
  • tree_sha256 시험 벡터, version_label 정제, Windows 인자 검사, 10,000자 자르기, ETag/304

hook 프로세스 테스트는 홈을 임시 폴더로 바꾸고 로컬 HTTP 서버를 origin으로 쓴다. 외부 의존성이 없다.

배포 환경 라이브 검증 수동 스크립트

  1. 등록자 API 키로 임시 스킬을 올린다
  2. 임시 HOME·프로젝트에서 실제 npx skills add로 설치하고 hook을 돌린다 → 최신
  3. 새 버전을 발행하고 serving이 바뀔 때까지 기다린다
  4. hook을 다시 돌려 업데이트 안내, 자동 재설치, 로컬 수정 시 거부를 확인한다
  5. 끝나면(실패·중단 포함) 임시 스킬을 지운다

CI 게이트가 아닌 수동 도구다. origin에 기본값이 없어 실수로 엉뚱한 서버를 두드리지 않는다.

서버와 PC가 같은 지문을 내는가가 이 구조의 전제다. 두 구현이 같은 시험 벡터를 쓰고, npx skills로 복사·전역·링크 설치본을 만들어 서버 값과 같은 트리가 나오는지 실측했다.

20 — 한계

아직 안 되는 것, 일부러 안 하는 것

에이전트는 Claude Code만 지원

운영체제 제약이 아니다 — Windows·macOS·Linux의 Claude Code에서 같은 hook이 돈다. OpenCode도 세션 생성 이벤트로 같은 일을 할 수 있어 보이지만 실측하지 않았다. 수요가 확인되면 정한다.

대상 에이전트는 -a claude-code 고정

lock이 설치 때 고른 에이전트를 남기지 않는다. 다른 에이전트에도 설치했다면 그쪽은 갱신되지 않는다.

R이 없는 설치본

plugin을 깔기 전부터 있던 설치본이 이미 뒤처져 있으면 첫 판정에서 업데이트·후퇴·로컬 수정을 가를 수 없다. 서버가 “이 지문은 몇 번째 버전인가”에 답하면 풀리지만, 과거 버전 지문을 익명으로 노출하는 범위가 넓어진다.

배포는 아직이다

서버 변경(인덱스 확장 필드·ETag)은 prod에 반영됐다. plugin을 prod 카탈로그 마켓에 등록하는 일은 남아 있어(#3307), 그 전에는 사용자가 카탈로그에서 받을 수 없다.

plugin 자신의 갱신

제3자 마켓이라 기본으로 자동 갱신이 꺼져 있다. hook이 자기 버전도 안내하는 기능은 보류했다.

범위 밖: 원본 git을 따르는 설치

내 마켓·GitHub 직행 설치는 serving 버전이 아니라 원본 저장소를 따른다. Claude Code와 git의 자체 갱신에 맡긴다.

인덱스 호출 수

short_id마다 한 번씩 묻는다. 스킬 수십 개 수준이면 24시간 TTL과 304로 충분하다고 본다. 묶음 조회가 필요한지는 사용량을 보고 정한다.

정리

서버는 지문을 내고, PC가 맞대 본다

익명 그대로

서버는 인덱스에 seq와 tree_sha256을 더했을 뿐이다. 누가 묻는지 기록하지 않는다.

판정은 L·S·R

내 폴더, 서버, 마지막으로 같았던 순간. 셋을 맞대면 업데이트·후퇴·로컬 수정을 가를 수 있다.

쓰는 자리에서 알린다

Claude Code 세션 시작 hook이 2초 안에 확인하고 Claude에게 안내를 넣는다. 실패하면 조용히 넘어간다.

자동은 켠 사람만, 안전하게

손대지 않은 복사 설치본만 잠금 → 백업 → 재확인 → 설치 → 검증 → 실패 시 복원을 거쳐 다시 설치한다.

한 문장으로 plugin을 설치해 두었다면, 스킬의 serving 버전이 바뀐 뒤 마지막 확인에서 24시간(TTL)이 지나 처음 여는 Claude Code 세션에서 Claude가 “업데이트가 있다”고 말해 준다. 자동 재설치를 켰고 손대지 않은 복사 설치본이면 그 자리에서 바꿔 준다.
