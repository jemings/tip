OpenAI API · Public Beta · 2026-09-10

Agent를 직접 만드는 대신, 실행 환경까지 맡긴다

OpenAI Agents API는 Codex를 구동해 온 agent harness를 API로 제공한다. 개발자는 모델 호출 loop와 장시간 세션 관리에 덜 신경 쓰고, Agent의 도구·지식·업무 흐름에 집중한다.

Betapublic beta
Codexharness foundation
Sessiondurable execution
MCPcustom tool ecosystem

기준일: 2026년 9월 13일. Agents API는 2026년 9월 10일 public beta로 공개됐다. [OpenAI Agents API announcement; Release Notes]

02 — 왜 지금인가

LLM 호출 → Agent 실행으로 추상화 수준이 올라갔다

기존 API 접근

애플리케이션이 모델을 호출하고, tool loop·state·retry·context 관리 등을 직접 조합한다.

Codex에서 얻은 교훈

긴 작업에는 강한 모델만으로 부족하다. context, tools, subagents, 실행 환경을 묶는 harness가 필요하다.

Agents API의 방향

그 harness와 인프라를 서비스로 노출해 “Agent를 만드는 일”의 기본 실행 루프를 표준화한다.

핵심 변화: “어떤 모델을 호출할까?”보다 “Agent가 며칠 동안 안정적으로 일을 계속하게 하려면 어떤 runtime이 필요한가?”에 초점이 이동한다. [OpenAI Agents API announcement; Harness engineering]
03 — 문제 정의

OpenAI가 대신 가져가는 것은 “Agent 운영의 귀찮은 부분”

Session orchestration

여러 턴에 걸친 Agent 실행을 관리하고 진행 상황을 스트리밍한다.

Context compaction

긴 세션이 context limit에 가까워지면 이전 context를 자동으로 압축해 계속 작업할 수 있게 한다.

Recovery

장시간 실행에서 필요한 복구 경로를 harness 차원에서 제공한다.

Tool orchestration

Agent가 도구를 사용하고 여러 단계의 작업을 수행하는 실행 loop를 managed harness가 담당한다.

공식 소개가 명시적으로 session orchestration, context compaction, recovery를 Agents API의 관리 기능으로 제시한다. [OpenAI Release Notes; Agents API announcement]

04 — 전체 구조

Agent = 설정 + Session + Environment + Tools

Application │ ▼ Agents API │ ├── Agent configuration │ ├─ model │ ├─ instructions │ └─ reasoning / metadata │ ├── Session │ ├─ durable state │ ├─ streamed events │ └─ long-running workflow │ └── Environment ├─ files ├─ packages ├─ network policy ├─ skills / plugins └─ code execution

Agent

재사용 가능한 설정 단위. 현재 API에는 model, instructions, metadata, multi-agent 설정 등이 포함된다.

Session

실제 업무를 수행하는 실행 단위. 초기 입력과 environment를 연결해 Agent를 돌린다.

Environment

Agent가 파일을 다루고 코드를 실행할 공간. OpenAI hosted 또는 자체/파트너 sandbox를 선택할 수 있다.

Agent 생성 API와 Session 생성 API가 각각 별도 리소스로 정의되어 있고, environment는 session 실행에 붙는다. [OpenAI API Reference: Agent; Session]

05 — Codex Harness

가장 중요한 것은 “OpenAI가 무엇을 재사용했는가?”

Codex와 같은 기반

Agents API는 Codex를 오랫동안 운영하며 다듬은 agent harness와 인프라를 개발자에게 제공한다.

Versioned capability

모델 출시와 함께 harness도 진화시키며, 개발자가 매번 orchestration을 다시 설계하지 않도록 한다.

Long sessions

수시간~수일 작업을 전제로 context 관리를 강화.

More tools

도구를 많이 붙였을 때의 사용 효율을 harness에서 개선.

Parallel subagents

한 Agent가 여러 subagent에게 작업을 나눠 병렬 처리 가능.

관전 포인트: OpenAI가 Agents API를 단순 SDK가 아니라 “Codex harness를 제품화한 것”으로 설명한다는 점이 핵심이다. [OpenAI Agents API announcement; Unlocking the Codex harness]
06 — Session & Context

“한 번의 request”에서 “계속 일하는 세션”으로

Session 생성

Agent 설정과 실행 environment를 연결하고 초기 input을 보낸다.

Tool-driven execution

모델 호출 → tool 실행 → 결과 반영을 반복한다.

Stream progress

실행 중 이벤트를 받아 UI나 orchestrator가 현재 상태를 표시한다.

Context compaction

긴 작업에서 이전 context를 압축해 흐름을 유지한다.

왜 중요한가?

실제 업무는 “한 질문에 한 답”보다 조사→수정→검증→대기→재개가 많다. Agent API의 핵심 차별점은 이 상태ful runtime을 API 표면으로 끌어왔다는 점이다.

API 관점

POST /agents로 재사용 Agent를 만들고, POST /agents/sessions로 managed session을 실행하는 리소스 구조가 제공된다.

Session 생성 API는 initial input, agent 설정, execution environment를 연결하고 stream 옵션을 제공한다. [OpenAI API Reference: Create an agent session]

07 — Execution Environment

Agent에게 “손과 작업대”까지 준다

OpenAI-hosted sandbox

OpenAI가 sandbox를 프로비저닝·관리한다. 파일, 코드 실행, artifact 생성이 가능하다.

Your infrastructure

자체 인프라에서 Agent가 코드와 파일을 다루게 하는 선택지도 제공한다.

Sandbox partners

지원되는 외부 sandbox provider와도 연결할 수 있다.

Environment template { files: [...], packages: { npm: [...], python: [...], system: [...] }, network: { access, allowed_domains }, skills: [...], plugins: [...], setup_commands: [...] }

특히 environment template은 매 session마다 새 환경을 만들 수 있는 재사용 가능한 실행 환경 구성이다.

공식 API reference에는 packages, network policy, setup commands, skills, plugins, files가 environment template의 구성 요소로 정의돼 있다. [OpenAI API Reference: Environment template]

08 — Tools · MCP

Agent의 능력은 Tools, 외부 확장은 MCP로 연결한다

Built-in / custom tools

Agent가 실제로 호출할 수 있는 capability를 도구로 구성한다. 애플리케이션의 내부 시스템도 custom tool로 연결할 수 있다.

MCP servers

기존 MCP 생태계를 활용해 외부 데이터와 도구를 Agent의 작업 공간에 연결한다.

filesystem / codeinternal APIsMCPweb/data toolsdomain workflows
구분: Agents API는 MCP 자체가 아니다. Agents API는 Agent runtime을 제공하고, MCP는 그 runtime이 외부 capability와 연결되는 한 가지 표준 경로다. 공식 소개에서도 “connect your own tools and MCP servers”를 명시한다. [OpenAI Release Notes; Agents API announcement]
09 — Subagents

하나의 Agent가 모든 일을 하지 않아도 된다

Main Agent │ ├── Research Agent │ └─ 조사 / 자료 수집 │ ├── Coding Agent │ └─ 구현 / 테스트 │ └── Review Agent └─ 검토 / 검증

왜 필요한가?

독립적인 작업을 병렬화하거나 역할별 context를 분리해 한 세션의 복잡도를 낮출 수 있다.

API 수준 지원

Agent 생성 API에는 명시적으로 multi_agent 설정과 max_concurrent_subagents가 존재한다.

OpenAI는 Agents API의 최근 harness 개선 예로 subagent 병렬화를 명시하고, API reference에서도 multi-agent configuration을 제공한다. [OpenAI Agents API announcement; Create an agent]

10 — Skills · Plugins

“Agent에게 무엇을 가르칠 것인가”도 Environment에 들어온다

Skills

재사용 가능한 업무 지식·절차를 Agent가 활용하도록 environment에 연결할 수 있다.

Plugins

환경에 함께 넣어야 할 기능이나 확장물을 패키지 형태로 제공할 수 있다.

A useful mental model Model = reasoning capability Agent = reusable behavior/configuration Session = ongoing work Environment = place to act Tools/MCP = capabilities Skills = domain/workflow knowledge

공식 environment schema가 skills와 plugins를 명시적으로 포함하고 있으며, hosted skill은 ID reference 또는 inline ZIP 형태로 제공할 수 있다. [OpenAI API Reference: Environment template / hosted skills]

11 — ACP와 비교

비슷해 보이지만 “경계”가 다르다

구분ACPOpenAI Agents APIMCP
핵심 문제Client ↔ Agent 연결Agent 실행·운영Agent ↔ Tool/Data 연결
정체ProtocolAPI + managed runtimeProtocol
대표 경계IDE / editor ↔ coding agentApplication ↔ agent runtimeAgent ↔ external capability
주요 가치상호운용성orchestration / sessions / environment도구·데이터 표준 연결

ACP

“어떤 client에서 어떤 agent를 사용할까?”

Agents API

“그 agent가 어떻게 오래 일하고 도구를 쓰게 할까?”

MCP

“그 agent가 바깥의 무엇과 연결될까?”

이 비교에서 Agents API는 OpenAI가 managed Codex harness를 API로 제공한다는 공식 설명에 기반한다. ACP와 MCP의 세부 사양 자체는 별도 프로젝트의 표준이므로, 이 자료에서는 관계를 개념적 계층으로 설명한다. [OpenAI Agents API announcement; Unlocking the Codex harness]

12 — Use cases

어떤 업무에서 특히 의미가 커지는가?

Long-running coding

repo 분석 → 수정 → 테스트 → 후속 작업처럼 수시간 이상 걸리는 개발 작업.

Research & analysis

자료 수집, 파일 처리, 반복 계산과 검증이 이어지는 조사형 업무.

Operational automation

사내 API, DB, 문서, CI 등을 연결해 업무를 끝까지 수행하는 자동화.

좋은 후보: 사람이 직접 매번 “다음에 무엇을 해야 하지?”라고 orchestration해야 하는 업무.
덜 필요한 경우: 한 번의 응답만으로 끝나는 단순 Q&A나 단발성 생성 작업.

OpenAI의 소개는 Agents API를 특히 long-running work, files/code, tools, subagents를 요구하는 Agent workload에 맞춘 기반으로 설명한다. [OpenAI Agents API announcement]

13 — Takeaways

이번 발표에서 가져갈 세 가지

1. Agent의 핵심은 모델만이 아니다

긴 작업에서는 context, tools, execution environment, recovery를 묶는 harness가 성능과 안정성을 좌우한다.

2. Agents API는 “runtime을 API화”한다

OpenAI가 Codex에서 다듬은 실행 구조를 managed service로 제공하는 것이 본질이다.

3. ACP / MCP와는 다른 층이다

ACP는 client↔agent, MCP는 agent↔capability, Agents API는 application↔agent runtime 쪽에 가깝다.

한 문장: Responses API가 “모델에게 요청하는 API”라면, Agents API는 “일을 맡길 실행 환경까지 포함한 API”에 가깝다.

다만 현재는 public beta다. OpenAI가 베타 동안 빠르게 반복 개선하겠다고 밝히고 있으므로 실제 도입 시 API 안정성과 운영 비용을 별도로 확인해야 한다. [OpenAI Agents API announcement]
