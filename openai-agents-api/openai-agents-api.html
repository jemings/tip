OpenAI Agents API · public beta · 2026-09-10

묻는 API에서, 맡기는 API로

Agents API는 Codex가 쓰는 에이전트 루프(harness)를 OpenAI 서버에서 대신 돌려 주는 API다. 오늘은 두 가지를 본다 — Chat Completions·Responses API에서 무엇이 달라졌는지, 그리고 같은 Codex를 ACP로 부를 때와 무엇이 다른지.

쉽게 말하면예전 API는 요리사에게 한 마디씩 물었고, Agents API는 요리를 통째로 맡긴다.

같은 오픈소스 Codex harness다. 다만 OpenAI 서버에서 도는 Codex의 버전·설정은 공개·고정되지 않는다. 비교 대상은 Zed·JetBrains에서 codex-acp로 쓰는 Codex.

Chat Completions · 묻기

요리사에게 한 마디씩 묻는다. 지난 대화는 내가 매번 들고 간다.

메시지 배열을 보내고 답 하나를 받는다. 모델이 도구를 쓰자고 하면 내가 실행하고 다시 묻는다. OpenAI 내장 도구는 쓸 수 없다.

Responses API · 도구 쥐여 주기

검색·코드 실행은 요리사가 직접 한다. 내 함수가 필요하면 멈추고 나를 부른다.

“combines the simplicity of Chat Completions with the tool-use capabilities of the Assistants API.” 그래도 “When used with custom tools, the Responses API yields control back to the client”.

Agents API · 맡기기

요리를 통째로 맡긴다. 요리사가 알아서 반복하고 주문 기록까지 보관한다.

“OpenAI manages sessions, orchestration, context compaction, and recovery while your application provides tools and chooses its execution environment.”

2막 — 같은 Codex, ACP와 무엇이 다른가

노트북을 닫으면, Codex는 계속 일할까?

쉽게 말하면집으로 부른 요리사는 불을 끄면 가고, 식당에 맡긴 요리는 내가 자도 계속된다.

에디터가 켜진 동안 끝날 일은 부르고(ACP), 나 없이 시작되고 계속 돌아야 할 일은 맡긴다(Agents API).

비교 범위: 같은 Codex harness를 내 컴퓨터에서 ACP로 잇느냐(Zed·JetBrains의 codex-acp), OpenAI에서 HTTPS로 잇느냐. Codex CLI·VS Code 확장도 왼쪽 편이다. ACP도 서버에서 돌릴 수는 있다 — 뒤에서 다룬다.

에디터를 닫으면 — codex-acp src/index.ts

process.stdin.on("close", () => {
    codexProcessState.connection.process.stdin.end();
    // Kill the codex process if it doesn't exit naturally
    setTimeout(() => {
        if (!codexProcessState.connection.process.killed) {
            logger.log("Codex still running 2s after stdin closed; terminating process");
            codexProcessState.connection.process.kill();
        }
    }, 2000);
});

기록은 ~/.codex/sessions에 남아 같은 컴퓨터에서 session/load·resume으로 대화를 잇는다. 멈춘 명령이 이어서 돌지는 않는다.

Agents API × Codex

세션 한살이 — 4단계

만들기

POST /v1/agents/sessions → session_id

지켜보기

스트림 GET …/events?stream=true, 또는 상태가 바뀔 때 webhook

말 걸기

POST …/events — message(쉬면 새 턴, 일하는 중이면 방향 바꾸기) · cancel · tool_result

치우기

DELETE …/sessions/{id}

주방(environment)은 셋 중 하나

none주방 없음 — 함수 도구·서비스 쪽 MCP·web search만
openai_hostedOpenAI 주방 — Linux /workspace, outputs는 artifact로 남음
self_hosted내 주방 — 내 노트북·Docker·파트너 샌드박스의 codex exec-server가 OpenAI로 먼저 연결

self_hosted여도 루프는 OpenAI에서 돈다. 스트림을 닫아도 작업은 취소되지 않고(“Closing an event stream does not cancel the task.”), 놓친 이벤트는 다시 오지 않는다 — 세션과 items를 조회해 복구한다.

끝까지 붙잡는 요청 vs 던져 두는 요청

쉽게 말하면ACP는 에디터가 전화를 끝까지 들고 있고, Agents API는 주문서를 넣고 끊어도 된다.

    for event in events:
        print(event.to_json(indent=None), flush=True)

“Closing an event stream does not cancel the task.” 나중에 다른 프로그램이 같은 session_id로 이어 말하거나 취소한다.

주의아래 두 코드는 같은 기능이 아니다 — 왼쪽은 프로토콜에 내장된 질문, 오른쪽은 내가 만든 질문에 대한 답이다

2막 — 예상 반론

“ACP로도 서버에서 돌리면 되잖아?” 된다. 대신 식당을 직접 차린다

쉽게 말하면집에서도 24시간 요리사를 둘 수 있다. 대신 식당 운영은 내가 다 해야 한다.

서버에서 돌리는 길 ACP로 — acpx(헤드리스 ACP CLI) · ACP SDK 클라이언트 · Zed SSH 원격 ACP 없이 — codex exec · Codex SDK · codex app-server --listen + codex --remote(실험적) 어느 길이든 떠안는 목록은 같다
누가 책임지나직접 운영 · Codex를 내 서버에서Agents API
24시간 켜 두기 항상 켜진 머신을 내가 운영 필요 없음루프와 세션은 OpenAI에 있다
죽으면 이어 하기 재기동 + session/resume기록은 그 디스크에만. acpx가 어댑터 재기동·resume을 일부 해 준다 세션이 서버에 남는다어느 머신에서든 session_id로 이어 간다
멀리서 부르기 · 알림 브리지를 직접 만든다표준 전송은 stdio뿐. 원격 HTTP/WebSocket RFD는 2026-07-02부터 Active 단계 — 작업 중, 확정 아님 HTTPS + session_idmessage로 방향 바꾸기, cancel, 상태 변화는 webhook

Agents API를 써도 내 몫 session_id·turn_id·call_id 저장 끊기면 세션·items를 조회해 복구 (재전송 없음) 부작용 있는 함수 결과는 두 번 보내도 안전하게 webhook을 쓰면 공개 HTTPS 주소 다 쓴 세션 DELETE self_hosted면 executor 준비·재연결·종료·파일 보존

샌드박스와 subagent는 로컬 Codex에도 있어 차이로 치지 않았다. 사람 없는 ACP는 권한 창을 띄울 사람도 없다 — acpx는 TTY가 없으면 권한 요청을 기본으로 거부한다.

3막 — 대신 받아들이는 것

식당에 맡기면, 식당 규칙을 따른다

쉽게 말하면맡기면 편하지만, 묻는 창도 화면도 내가 만들어야 한다.

설계상 내려놓는 것 · 오래 갈 것

  1. 묻는 장치도 화면도 없다. 명령 실행·파일 수정·MCP 호출에 승인 설정이 없다 추론 · 문서·SDK 타입 기준. 필요하면 함수 도구로 직접 만들고, 채팅·diff 화면도 직접 만든다. 대시보드(Logs → Agents)는 개발자용 조회 화면이다.
  2. ChatGPT 구독으로 쓰는 방법이 문서에 없다. API 키 종량제다 추론.
  3. 로컬 Codex 조작판이 없다. config.toml·승인 모드·슬래시 커맨드(/review 등)가 없고, OpenAI 주방은 CODEX_* 환경변수를 거부한다. 서버의 Codex 버전은 공개·고정되지 않는다. AGENTS.md를 따르는지는 문서에 없다 미검증.
  4. OpenAI 주방은 활동·keep-alive가 1시간 끊기면 삭제될 수 있다. 설정할 수 없고, /workspace/outputs 파일만 artifact로 남는다.
  5. 코드를 넣고 꺼내는 길은 내가 만든다. 업로드·setup 명령이나 clone·마운트로 넣는다. 수정부터 PR까지 가는 공식 예제는 없다.

베타라서 · 바뀔 수 있음

  • 데이터 레지던시는 현재 미국만 지원, ZDR 미지원 (self_hosted여도 같음)
  • OpenAI-Beta: agents=v1 헤더 필요, 외부 trace exporter 없음, 전용 rate limit 문서 없음, 일부 샌드박스 파트너는 preview·beta

주의 추론 · 공개 문서 기준

  • 내 노트북을 주방으로 쓸 때 울타리가 있다고 가정하지 말 것. exec-server는 요청받을 때만 샌드박스를 걸고, OpenAI 쪽이 요청하는지는 문서에 없다. OpenAI도 “Run workloads in isolated compute, such as virtual machines.”를 권한다.
  • 승인을 얼마나 기다려 주는지, 그동안 OpenAI 주방이 살아 있는지는 문서에 없다.

ACP 쪽도 공짜는 아니다. codex-acp가 기대는 Codex App Server는 문서상 “experimental and isn't supported for production workloads”이고, 표준 원격 전송이 없으며, app-server가 죽으면 다시 띄우지 않는다.

쉽게 말하면켜 둔 동안 끝날 일은 부르고, 나 없이 돌 일은 맡긴다.

OpenAI가 맡는 몫이 늘었다

Chat Completions는 기억·루프·도구가 모두 내 몫. Responses는 내장 도구·기억 옵션·background를 얹었고, Agents API는 루프·세션·압축·복구·작업대까지 가져갔다. 내 함수 실행은 끝까지 내 몫이다.

ACP는 부르는 Codex

설치하면 끝, 권한 창과 diff가 공짜, ChatGPT 구독으로 쓸 수 있다. 대신 에디터가 꺼지면 멈춘다.

Agents API는 맡기는 Codex

나 없이 시작해 계속 돌고, session_id로 어디서든 이어 가고, 끝나면 webhook이 온다. 대신 승인·화면은 직접 만들고, 종량제·미국 레지던시·베타를 받아들인다.

에디터가 켜진 동안 끝날 일은 부르고(ACP), 나 없이 시작되고 계속 돌아야 할 일은 맡긴다(Agents API).

ACP v2 초안의 비동기 턴(running · idle · requires_action)과 Active 단계의 원격 전송 RFD가 이 간극을 줄일 수 있다. 오늘은 둘을 잇는 공식 브리지가 없다 추론.
