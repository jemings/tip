Agent Observability · OpenTelemetry · 2026-10

Agent가 45초 걸렸다. 어디서 막혔을까?

AI Agent는 부탁 한 번에 모델·tool·MCP 서버를 여러 번 오간다. 답만 봐서는 어디서 시간이 갔는지 모른다. OpenTelemetry(OTel)는 그 길을 구간별로 남기는 공용 규칙이다.

쉽게 말하면택배가 늦으면 송장 번호로 배송 조회를 연다. 집하 → 허브 → 배송 출발, 어느 구간에서 멈췄는지 한눈에 보인다. Agent에도 송장 번호를 붙이자는 것이 오늘 이야기다.

Trace송장 번호 하나 = 부탁 한 번
Span구간 한 줄 = 모델·tool 호출 하나
gen_ai.*Agent용 공용 이름표
Development이름표는 아직 시범 운영 중
요약 — 먼저 결론

오늘 가져갈 두 문장

1. Agent의 부탁 한 번은 여러 구간을 지나는 택배다

모델 호출, tool 실행, MCP 서버 호출이 각각 한 구간이다. 구간마다 한 줄(span)을 남기고 송장 번호(trace)로 묶으면, 어디서 시간이 갔는지 막대 길이로 보인다.

2. OTel은 모든 택배사의 송장 양식을 하나로 맞춘다

기록하는 법, 보내는 법, 부르는 이름을 정한다. 한 번 심어 두면 Jaeger든 Langfuse든 Datadog이든 어느 조회 화면으로든 보낼 수 있다.

그래서“Agent가 느려요”가 “위키 저장 API가 429를 받아 35초를 기다렸어요”로 바뀐다.

05 — OpenTelemetry가 정하는 것

송장 쓰는 법, 보내는 법, 부르는 이름을 모두 같게

내 Agent+ OTel SDK
구간마다 span을 남긴다
OTLP공용 전송 형식
Collector모으고·거르고·나눈다
(없어도 된다)
OTLP그대로 넘긴다
조회 화면 (backend)Jaeger · Grafana · Langfuse · Datadog …

① 기록하는 법 API · SDK

span을 열고 닫고, 송장 번호를 다음 구간에 넘긴다. Python·JS·Go·Java 등 언어마다 있다.

택배로 치면 → 송장 양식

② 보내는 법 OTLP · Collector

기록을 공용 형식(OTLP)으로 보낸다. Collector는 중간 허브다. 모아서 거르고, 여러 곳에 나눠 보낸다.

택배로 치면 → 택배사 공용 전산망

③ 부르는 이름 Semantic Conventions

span과 이름표에 붙일 이름. “모델 호출은 chat, 입력 토큰은 gen_ai.usage.input_tokens”처럼 정한다.

택배로 치면 → “집하·배송출발” 같은 단계 이름

OTel은 조회 화면이 아니다. 기록을 저장하고 그려 주는 곳(backend)은 따로 고른다. 화면을 바꿔도 Agent 쪽 코드는 그대로다.

OTel이 남기는 신호는 세 가지다. Trace(구간별 조회), Metric(“이번 주 평균 몇 초” 같은 통계), Log(그 순간의 메모). 오늘은 Trace를 중심으로 본다.

06 — GenAI Semantic Conventions

Agent용 단계 이름도 정해져 있다

구간span 이름대표 이름표 (attribute)
Agent 실행 한 번invoke_agent {Agent 이름}gen_ai.agent.name · gen_ai.conversation.id
모델 호출chat {모델}gen_ai.request.model · gen_ai.usage.input_tokens · gen_ai.usage.output_tokens
tool 실행execute_tool {tool 이름}gen_ai.tool.name · gen_ai.tool.call.id
MCP 호출tools/call {tool 이름}mcp.method.name · mcp.session.id
실패했을 때어느 span이든error.type
 
# 04의 세 번째 모델 호출을 열어 보면
span      chat claude-sonnet-5-5   (CLIENT)
trace_id  4bf92f3577b34da6a3ce929d0e0e4736
parent    invoke_agent meeting-summarizer

gen_ai.operation.name       chat
gen_ai.provider.name        anthropic
gen_ai.request.model        claude-sonnet-5-5
gen_ai.usage.input_tokens   6210
gen_ai.usage.output_tokens  480
gen_ai.response.finish_reasons  ["tool_use"]

이름이 같으면 질문도 같다

“모델별 입력 토큰 합계”, “tool별 실패율”을 어느 Agent에서 왔든 같은 쿼리 하나로 뽑는다.

더 있다

plan(계획 세우기), invoke_workflow(여러 Agent 묶음), create_agent, 메모리 작업(search_memory 등). 필요한 것만 쓴다.

쉽게 말하면택배사마다 “배송출발”을 “출고”, “발송”, “상차”로 따로 적으면 한 화면에 모을 수 없다. 단계 이름을 하나로 정해 두는 것이다.

이 이름표는 전부 Development 단계다(13). plan과 메모리 작업은 아직 릴리스 전(main 브랜치)이다.

07 — MCP 서버 안까지

다른 프로그램으로 넘어가도 송장 번호가 따라간다

04의 save_page 37.1초를 확대하면
10s20s30s40s
execute_tool save_page · Agent37.1s
tools/call save_page · MCP 서버36.9s
PUT /api/pages → 42915초 대기0.4s
PUT /api/pages → 42920초 대기0.4s
PUT /api/pages → 2000.9s
// Agent → wiki-mcp 서버로 가는 MCP 요청
{ "jsonrpc": "2.0", "id": 7, "method": "tools/call",
  "params": {
    "name": "save_page",
    "arguments": { "title": "10/6 주간회의 요약", … },
    "_meta": {
      "traceparent": "00-4bf92f35…4736-00f067aa0ba902b7-01"
    }
  }
}

어떻게 이어지나

Agent가 요청의 params._meta에 traceparent(송장 번호 + 보낸 구간 번호)를 넣는다. 서버는 그 값을 부모로 삼아 자기 span을 만든다. 언어가 달라도, 다른 컴퓨터여도 같은 trace에 붙는다.

왜 HTTP 헤더가 아니라 메시지 안에

MCP는 stdio로도 돈다. 그러면 헤더가 없다. HTTP여도 요청 하나에 MCP 메시지가 여럿 오갈 수 있다. 그래서 메시지마다 싣는다.

진범: 위키 API의 429(요청이 너무 많음). 실제로 일한 시간은 1.7초, 기다린 시간이 35초다. 모델을 바꿨다면 여전히 40초가 넘었을 것이다. 고칠 곳은 위키 API 호출 한도다.

쉽게 말하면다른 택배사로 넘겨 배송하더라도 송장 번호가 같이 넘어가면, 한 조회 화면에서 끝까지 보인다.

스펙: Agent가 이미 execute_tool span을 만들면 MCP 계측은 span을 또 만들지 않고 거기에 mcp.* 이름표만 붙인다. 그래서 Agent 쪽 줄이 하나다.

08 — 같은 일, 다른 이름표

둘 다 OTel로 내보내는데, 이름이 다르다

Claude Code(trace는 beta)와 GitHub Copilot CLI는 둘 다 OTel trace를 내보내고, 둘 다 Claude 모델을 부를 수 있다. 같은 일을 어떻게 적는지 나란히 놓으면:

같은 일Claude CodeGitHub Copilot CLI
부탁 한 번claude_code.interactioninvoke_agent
모델 호출claude_code.llm_requestchat {모델}
tool 실행claude_code.toolexecute_tool {tool}
tool 이름tool_namegen_ai.tool.name
입력 토큰input_tokens — 캐시 토큰은 빠져 있다. 표준 값을 얻으려면 캐시 두 칸을 더한다gen_ai.usage.input_tokens
토큰 지표claude_code.token.usagegen_ai.client.token.usage

다른 도구도 제각각

Codex는 codex.*, Gemini CLI는 gemini_cli.*에 일부 gen_ai.*를 같이 쓴다. Copilot CLI 문서는 “모든 이름이 GenAI Semantic Conventions를 따른다”고 적는다.

그래서 누군가 환산표를 만든다

Honeycomb 문서는 Claude Code 데이터를 Collector의 transform으로 gen_ai.* 이름에 맞추는 법을 따로 싣는다. Phoenix는 gen_ai.*를 자기 이름으로 바꿔 읽고, Langfuse는 두 이름을 다 읽는다.

쉽게 말하면같은 무게를 한쪽은 kg, 한쪽은 근으로 적은 셈이다. 한 저울에 올리려면 환산표가 필요하다. 표준 이름표는 그 환산표를 없앤다.

어느 쪽이 나쁘다는 이야기가 아니다. Claude Code도 gen_ai.request.model·gen_ai.tool.call.id 같은 표준 이름을 일부 같이 붙이고, 표준 값으로 바꾸는 법을 문서에 적어 둔다. 표준이 아직 움직이는 중이라 생긴 차이다(13).

지금 쓰는 코딩 Agent의 배송 조회를 열어 보자

# ① 조회 화면 띄우기 — Grafana·Tempo·Loki·Prometheus 한 통
docker run --rm -p 3000:3000 -p 4317:4317 -p 4318:4318 \
  grafana/otel-lgtm

# ② Claude Code가 거기로 보내게 (다른 터미널에서)
export CLAUDE_CODE_ENABLE_TELEMETRY=1
export CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1  # trace는 beta

export OTEL_METRICS_EXPORTER=otlp

export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
claude

# ③ http://localhost:3000 → Explore → Tempo

무엇이 보이나

claude_code.interaction 아래로 모델 호출과 tool 막대가 늘어선다. Metric 쪽에는 claude_code.cost.usage(USD)와 claude_code.token.usage가 쌓인다.

tool 막대 안을 열면

blocked_on_user(내 승인을 기다린 시간)와 execution(실제 실행)이 따로 찍힌다. Agent가 느린 줄 알았는데 내가 승인 버튼을 늦게 눌렀을 수도 있다.

다른 Agent라면

  • Copilot CLI — COPILOT_OTEL_ENABLED=true와 OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
  • Codex — ~/.codex/config.toml의 [otel]에서 exporter와 trace_exporter를 { otlp-grpc = { endpoint = "http://localhost:4317" } }로
  • Gemini CLI — .gemini/settings.json의 telemetry.enabled: true. 보내는 곳 기본값이 localhost:4317이다. 프롬프트가 기본으로 남으니 logPrompts: false도 같이(10)

해 보면04의 그림이 내 Agent로 그려진다. 막대 한 줄 한 줄이 방금 내가 시킨 일이다.

기본 설정으로는 프롬프트 원문이 남지 않는다(10). 회사에서 관리자가 OTel 설정을 내려 주고 있다면 그 설정이 우선할 수 있다.

10 — Prompt도 남길까

송장에 상자 속 내용까지 적지는 않는다

① 안 남긴다 기본값

모델·토큰·시간·tool 이름만 남긴다. 04~07의 수사는 이것만으로 다 됐다.

② span에 바로 남긴다 개발·테스트

gen_ai.input.messages·gen_ai.output.messages에 대화 원문을 넣는다. 재현은 쉽지만 trace를 보는 모두가 원문을 본다.

③ 따로 두고 위치만 운영 권장

원문은 별도 저장소에 두고, span에는 그 위치만 적는다. 저장소에 접근 권한을 따로 건다.

도구프롬프트 원문 (기본값)켜는 법
Claude Code안 남김 (길이만)OTEL_LOG_USER_PROMPTS=1
Copilot CLI안 남김OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true
Codex안 남김 (tool 결과는 앞부분이 남는다)log_user_prompt = true
Gemini CLI남김logPrompts 기본값이 true. 회사 코드라면 false부터

쉽게 말하면송장에는 “서류 1박스”까지만 적는다. 내용물 사진은 따로 금고에 넣고, 송장에는 금고 번호만 적는다.

스펙: “계측은 기본으로 지시문·입력·출력을 남기지 말아야 하고(SHOULD NOT), 사용자가 켤 수 있는 옵션을 줘야 한다.” ③은 스펙이 운영 환경에 권하는 방식이다.

11 — 언제 쓰나

첫 질문 하나로 고른다

Agent가 “왜 그랬는지”를 숫자로 설명해야 하나?

예 → trace를 켠다

  • 느리다 — 어느 구간에서 시간이 갔나 (04·07)
  • 비싸다 — 어느 모델·Agent·사람에게서 토큰이 나갔나
  • 맴돈다 — 부탁 한 번에 execute_tool이 몇 번 찍혔나
  • 여럿이 쓴다 — 팀 전체의 사용량·비용·승인 거부를 한 화면에
  • MCP 서버를 만들어 남에게 준다 — 내 서버의 span이 손님 trace에 그대로 붙는다

아니오 → 아직은 없어도 된다

  • 혼자 가끔 돌려 보는 실험 — 터미널 출력으로 충분하다
  • 답이 맞았는지 채점하기 — trace는 “무엇을 했나”를 보여 줄 뿐이다. 채점은 평가(eval) 도구가 한다

시작 순서① 쓰고 있는 코딩 Agent에서 켜 본다(09) → ② 만드는 Agent에 붙인다(12) → ③ 내 MCP 서버·tool까지 송장 번호를 잇는다(07).

12 — 내가 만드는 Agent에 붙이기

세 갈래 중 쉬운 길부터

① framework 스위치 켜기

이미 OTel이 들어 있다. Google ADK, Pydantic AI, Microsoft Agent Framework는 표준 이름을 그대로 낸다.

Strands Agents는 옛 이름이 기본이라 OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental를 켠다. Vercel AI SDK 7은 @ai-sdk/otel을 붙인다.

② 계측 라이브러리 얹기

내 코드는 그대로 두고 SDK 호출을 감싼다. OTel 공식 opentelemetry-python-genai(openai, anthropic, openai-agents, langchain 등), OpenLIT, OpenLLMetry, OpenInference.

OpenAI Agents SDK는 기본으로 OpenAI 대시보드에 trace를 보낸다. OTel로 받으려면 이 길로 간다.

③ 직접 span 심기

모자란 구간만 손으로 감싼다. 이름만 표준을 따르면 된다.

from opentelemetry import trace
tracer = trace.get_tracer("meeting-summarizer")

with tracer.start_as_current_span(
        "execute_tool save_page") as span:
    span.set_attribute("gen_ai.operation.name",
                       "execute_tool")
    span.set_attribute("gen_ai.tool.name", "save_page")
    wiki.save_page(title, body)  # 원래 코드

이렇게 감싸 두면 04의 execute_tool save_page 막대 한 줄이 생긴다.

받는 쪽은 아무거나 범용 화면(Jaeger, Grafana Tempo)이든 LLM 전용 화면(Langfuse, Arize Phoenix, Datadog LLM Observability, LangSmith)이든 모두 OTLP를 받는다. 화면을 바꿔도 ①~③은 그대로다.

이름표가 다른 계측도 있다. OpenInference는 자체 이름(llm.token_count.prompt)이 기본이고, 표준 이름은 옵션(OPENINFERENCE_ENABLE_GENAI_SEMCONV)으로 같이 낸다. CrewAI에 들어 있는 telemetry는 익명 사용 통계라 내 backend로 오지 않는다.

지금 상태

GenAI·Agent·MCP 이름표는 전부 Development이고, 새 저장소는 아직 릴리스가 없다. 예를 들어 토큰 지표 gen_ai.client.token.usage는 main에서 다른 이름으로 바뀌었지만, 지금 도구들은 이 이름을 쓴다.

그래서 붙일 때

어느 버전의 이름을 내는지 적어 둔다. 라이브러리에 OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental 같은 스위치가 있는지 본다. 화면(backend)이 어느 이름을 읽는지 확인한다.

쉽게 말하면송장 양식의 칸 이름은 아직 시범 운영 중이라 바뀔 수 있다. 그래도 송장 번호로 구간을 잇는 trace·span 자체는 OTel에서 오래 써 온 안정된 뼈대다.
